## 一句话说清

AI 已经能替人干活了，但"会用 AI 改造自己生意"的企业还是少数。

领猫不替客户做定制开发——那既贵，交付体验也不会好。我们把自己的位置放在**底座**：把数据汇聚、数据清洗、宽表制作、应用发布、权限治理、规则知识库、历史数据复利这些基础设施做扎实；**具体的看板、报表和指标，交回给最懂自己生意的你**。

这个仓库是这条路径的入口：**方法、口径、示例全开放。你带来经营问题，你的 AI Agent 带来执行力，领猫提供可靠的底层数据与业务语义。**

## 这个仓库给你什么

| 模块 | 你会拿到什么 |
|---|---|
| **接入** | 让你的 AI Agent 安全连上领猫 SCM：授权、最小只读验证、故障排查 |
| **知识** | 业务术语、指标口径、流程与状态前提——一个定义只维护一处 |
| **场景** | 研发、采购、生产、交期、库存、成本、协同的高频问题，给出可复现的做法 |
| **资产** | 可被 Agent 直接读取的接入文档、模拟数据与检查工具 |

## 领猫 SCM 是什么

领猫 SCM（LinkMore）是领猫科技自 2016 年起持续深耕服装服饰行业的智慧供应链协同平台，围绕 **「款准时上市、货准时交付、财算得清」** 三大目标，把款式研发、物料采购、生产跟单、入库与供应商对账连成一条链，让跨部门、跨企业的进度、责任和成本有据可查。

- 贯通：企划 · 设计 · 打样 · 评审 · 物料 · 订单 · 采购 · 生产 · 品控 · 财务 · 供应商协同
- 对接 OMS / ERP / POS / FMS / MES / RFID，构建无边界的协同网络
- 已服务 1000+ 客户、9000+ 品牌，协同 42 万余个产业上下游资源
- 官网：<https://www.cnunify.com>

## 三步开始

**第一步** 把下面这句话交给你的 AI Agent（WorkBuddy、Codex 等任何能读文件、能调接口的 Agent 都可以）：

> 读取 <https://github.com/IfLinkIf/linkmore-scm-ai-agent-playbook/blob/main/START_HERE.md>，按流程帮我接入领猫 SCM，并完成最小验证。

**第二步** Agent 按流程带你走完：环境检查 → 授权 → 最小只读查询 → 接入报告。

**第三步** 告诉它你关心的经营问题（例如"本周哪些订单有延期风险"），它按仓库里的场景方法取数、核对、给结论。

## 仓库结构（目标）

```
linkmore-scm-ai-agent-playbook/
├── README.md            # 总入口：人类与 Agent 都从这里开始
├── START_HERE.md        # Agent 接入与知识导航流程
├── catalog.yaml         # 已发布内容索引（由内容元信息生成）
├── CONTRIBUTING.md      # 贡献指南
├── GOVERNANCE.md        # 审核、维护与发布规则
├── SECURITY.md          # 敏感信息与安全问题报告方式
│
├── connect/             # 如何接入领猫 SCM
│   ├── authorization.md #   客户授权与凭证配置
│   ├── api.md           #   API 接入方式
│   ├── verify.md        #   最小接入验证
│   └── troubleshooting.md
│
├── knowledge/           # 权威知识：一个定义只维护一处
│   ├── glossary/        #   业务术语
│   ├── metrics/         #   指标与统计口径
│   ├── workflows/       #   流程、状态与操作前提
│   └── data-mapping/    #   数据对象与关联关系
│
├── playbooks/           # 按经营问题组织的实战场景
├── skills/              # 已验证的 Agent 场景执行指引
├── tools/               # 接入检查、取数等必要工具
├── examples/            # 可运行案例与模拟数据
├── templates/           # 知识条目、场景与验证记录模板
└── checks/              # 文档、索引与示例的自动检查
```

首版**只创建有真实内容的目录**，不预先把空栏目铺满。

三个层次别混淆：**knowledge** 回答"概念、字段、流程是什么"；**playbooks** 回答"遇到这个经营问题该怎么办"；**skills** 回答"Agent 应按什么步骤完成这件事"。规则只维护在权威来源，场景与技能引用它，不复制。

## 给 AI Agent 的约定

- 先读 [START_HERE.md](START_HERE.md)，判断用户是要**接入**、要**学技巧**，还是**解决具体问题**。
- 按需读取相关内容，**不要一次性加载整个仓库**；只读接入不等于全库下载。
- 不推测接口地址、授权方式、字段含义或"已支持"的功能。
- 不索取、不公开密钥、原始对话、客户单据与企业敏感经营数据；日志与报错默认脱敏。
- 关键流程以 README 与 START_HERE 的显式链接为准，不要假设 Agent 会自动读取约定文件。
