# skills —— Agent 技能库

这里的每一条，都是**能给 AI Agent 照着执行的操作指引**。用户把自己的 AI Agent（WorkBuddy、Codex、ChatGPT、豆包办公、千问办公等）接上领猫 SCM 之后，把这条技能交给它，它就能按步骤把一件事做完。

三个层次不要混：`knowledge/` 回答「概念、字段、流程**是什么**」；`playbooks/` 回答「遇到这个经营问题**该怎么办**」；**`skills/` 回答「Agent 应该按什么步骤把它做完」**。口径只在 `knowledge/` 里维护，技能里引用它，不复制。

## 一条技能该长什么样

- **目标**：一句话说清做完什么
- **适用前提**：系统版本、模块、权限、需要的数据——没有写的就是没确认，不推测
- **输入**：Agent 需要用户提供什么，哪些可以自己判断
- **步骤**：按顺序做什么，每一步的判断依据是什么
- **输出**：产出什么形态（清单 / 报表 / 提醒 / 结论），给谁看
- **异常处理**：**无数据 / 无权限 / 连接失败**——三者含义完全不同，分别怎么回答用户
- **边界**：明确不做什么（不写入、不批量导出、不代做报价与交付承诺）
- **验证记录**：作者、维护人、最近验证日期、验证状态

## 怎么投稿

1. 复制 [`TEMPLATE-SKILL.md`](TEMPLATE-SKILL.md)，改名为 `你的技能名.md`，填完放进本目录。
2. 一并更新 `knowledge/` 里被引用的口径（如果没有就新建），**一个定义只维护一处**。
3. 提 Pull Request；不会提 PR 就在 Issue 里贴，由负责人转成提交。

## 红线

技能与示例中不允许出现：密钥与 Token、客户名称、单据与聊天记录、真实经营数据与价格、未公开的战略 / KPI / 人事信息。日志与报错默认脱敏。**脱敏必须在上传之前完成**——公共 PR 在提交的那一刻就已经公开了。

## 状态标注

每条技能必须标状态，不允许模糊：

| 状态 | 含义 |
|---|---|
| 草稿 | 方法有了，还没人跑通过 |
| 已验证 | 至少在内部环境完整复现过，记录在案 |
| 客户现场复现 | 在真实客户环境跑通，客户确认结果可用 |
| 已弃用 | 版本变更或方法失效，保留作历史参考 |
